# Evaluator Framework

A Python framework for running LLM judges on generic outputs with structured storage and analysis.

## Getting Started

```bash
export OPENAI_API_KEY="your-api-key-here"
export OPENAI_BASE_URL="https://api.openai.com/v1"  # Optional, defaults to OpenAI's API
uv init my-evaluator
cd my-evaluator
uv add "evaluator @ git+https://github.com/mcolyer-shopify/evaluator"
```

Create a file called `simple_judge.py`:

```python
from evaluator import CSVSource, XMLFormatter, ResponsesLLM, Evaluator
from pydantic import BaseModel, Field

class QualityJudge(ResponsesLLM):
    name = "quality_judge"
    model = "gpt-5"
    reasoning_effort = "medium"
    
    prompt = """You are an expert content evaluator.

Rate content quality from 0-1 based on:
- Clarity and coherence
- Factual accuracy
- Completeness
- Overall usefulness

Provide detailed reasoning for your score.

Evaluate the quality of this content and provide a score:

{formatted_input}"""

    class OutputFormat(BaseModel):
        """Structured output format for quality evaluation."""
        score: float = Field(description="Quality score from 0-1", ge=0.0, le=1.0)
        reasoning: str = Field(description="Explanation of the score")

# Set up and run evaluation
def main():
    # Make sure you have OPENAI_API_KEY set
    source = CSVSource("data.csv")  # Your CSV file with data
    formatter = XMLFormatter()
    
    evaluator = Evaluator(
        source=source,
        formatter=formatter,
        judges=[QualityJudge()],
    )
    
    evaluator.run_sync()
    
    # Get results
    stats = evaluator.get_stats()
    print(f"Processed {stats['total']} items")

if __name__ == "__main__":
    main()
```

### CSV Column Mapping

The CSVSource supports optional column mapping to select and rename columns. This is especially useful when working with existing CSV files that don't match your expected format.

**Example CSV file (`feedback.csv`):**
```csv
ticket_id,customer_message,support_response,created_at,resolved,internal_notes
T-1001,How do I reset my password?,Please visit account settings...,2024-01-15,true,Customer contacted twice
T-1002,Product not working,We'll investigate this issue...,2024-01-16,false,Escalated to engineering
```

**Using column mapping to extract only what you need:**

```python
# Map CSV columns to your evaluation format
source = CSVSource(
    "feedback.csv",
    column_mapping={
        "ticket_id": "id",                    # Required: map to 'id' field
        "customer_message": "question",       # Rename for clarity
        "support_response": "answer",         # Rename for clarity
        "created_at": "timestamp",            # Include metadata
        # resolved and internal_notes columns are ignored
    }
)

# Result: Each row becomes:
# {
#     "id": "T-1001",
#     "question": "How do I reset my password?",
#     "answer": "Please visit account settings...",
#     "timestamp": "2024-01-15"
# }
```

**Without mapping (requires 'id' column to exist):**
```python
source = CSVSource("data.csv")  # All columns included as-is
```

**Benefits:**
- **Select specific columns** from large CSV files with many fields
- **Rename columns** to match your evaluation format
- **Filter out sensitive data** like internal notes or PII
- **Map existing identifiers** to the required 'id' field
- **Clean up data** by excluding irrelevant columns

### Adding New Analyzers

Analyzers automatically run after evaluation completes when provided to the Evaluator:

```python
from evaluator.base import Analyzer
import numpy as np

class StatisticalAnalyzer(Analyzer):
    def analyze(self, results: list[dict]) -> str:
        scores = [r.get("judge_quality.score", 0) for r in results]
        return f"Mean: {np.mean(scores):.3f}, Std: {np.std(scores):.3f}"

# Use in evaluator - runs automatically after evaluation
evaluator = Evaluator(
    source=source,
    formatter=formatter,
    judges=[MyJudge()],
    analyzers=[StatisticalAnalyzer()],  # Runs automatically
    show_progress=True  # Shows analysis results
)

evaluator.run_sync()  # Both evaluation and analysis happen
```

### Output Storage

Results are stored in a DuckDB file with the following column structure:

- `id` - Unique identifier for each evaluation item
- `input` - The formatted input sent to judges
- `judge_{name}.{metric}` - Judge-specific metrics (e.g., `judge_quality.score`, `judge_quality.reasoning`)
- `judge_{name}.meta.tokens_total` - Total tokens used by the judge
- `judge_{name}.meta.tokens_prompt` - Prompt tokens used by the judge
- `judge_{name}.meta.tokens_completion` - Completion tokens generated by the judge
- `judge_{name}.meta.tokens_cached` - Cached tokens (for prompt caching optimization)
- `judge_{name}.meta.latency_ms` - Judge execution time in milliseconds
- `judge_{name}.error` - Error message if the judge failed (null if successful)

### Viewing Results

Use the built-in web viewer to browse and analyze evaluation results:

```bash
# View results from default directory (./results)
uv run evaluator viewer

# View results from custom directory
uv run evaluator viewer --results-dir /path/to/results

# Use custom port
uv run evaluator viewer --port 8080
```

The viewer automatically loads the most recent dataset and provides:
- Row-by-row navigation of evaluation results
- Dynamic filtering on judge outputs
- Side-by-side view of inputs and judge results
- Dataset switching for comparing multiple evaluations

### Configuration Options

#### Cache Warmup

```python
# Default behavior - cache warmup enabled
evaluator = Evaluator(
    source=source,
    formatter=formatter, 
    judges=[MyJudge()],
)

# Disable cache warmup
evaluator = Evaluator(
    source=source,
    formatter=formatter,
    judges=[MyJudge()],
    warmup_cache=False,
)

## Development

The project includes a comprehensive test suite with mocked LLM calls for fast execution.

### Test Setup

```bash
# Install test dependencies (included in dev dependencies)
uv sync --dev

# Run all tests
uv run pytest tests/ -v

# Run with coverage report
uv run pytest --cov=src/evaluator --cov-report=term-missing tests/

# Run tests in parallel for faster execution
uv run pytest -n auto tests/

uv run pytest -m "not slow" tests/
